# Performance plan: feat/saved-loadouts (2026-09-08)

Goal: tab switches and every interaction (slider drag, typing, clicking mod cells, opening the editor drawer, scrolling the armor table) should feel instant.

This plan comes from a code review of the branch. Every finding below was confirmed by reading the code paths. Line numbers were correct on 2026-09-08 against the working tree (which has uncommitted changes); re-check them before editing.

## Ground rules

- Read `AGENTS.md` first. This Next.js version differs from training data; consult `node_modules/next/dist/docs/` before touching routing, `next/image`, or config.
- `cacheComponents: true` is already on. Both routes stay mounted through React `<Activity>` (verified in headless Chrome: two `<main>` elements, the hidden one is `display: none`). Do not try to "fix" tab switching by restructuring routes. Remember Activity runs effect cleanups on hide and effects again on show, so keep effects idempotent.
- No React Compiler is configured, so `memo` boundaries only hold when props are referentially stable. Every `memo` added must come with stable callbacks (`useCallback`) and hoisted or memoized objects.
- Base UI tooltips do not mount their popup while closed, but each `TooltipLabel` still creates a Tooltip root (a store plus ~25 hooks across root and trigger). Treat per-cell and per-row tooltips as expensive.
- Make surgical changes. Do not refactor unrelated code, rename things, or change visuals beyond what an item calls for.
- After each phase: `npm run lint`, `npm test`, and `npx tsc --noEmit`. For phases that touch layout, take a screenshot in the running app and compare with before.
- Commit per phase with a message describing the user-visible effect.

## How to measure

Signed-in timing needs the real browser (the Bungie session cookie lives there). Use the React DevTools Profiler on:
1. One slider drag in the optimizer.
2. One search run completing (progress bar to results).
3. Opening the loadout editor drawer from the sidebar.
4. Typing five characters into the drawer's Name field.
5. Typing five characters into the armor table search, and one column hover.

Record commit counts and durations before Phase 1 and after each phase. Headless Chrome cannot sign in, so do not rely on it for these numbers. The in-editor preview webview cannot load the dev server (self-signed cert on `https://localhost:4321`).

## Phase 1: Optimizer panel (`/`)

### 1a. Stop slider drags from re-rendering all 50 build rows

File: `src/components/builder/builder-panel.tsx`

- `setTarget` (~line 614) updates `targets` on every pointer move from the Base UI slider.
- `builderSnapshot` (~line 697) is memoized on `targets`, and `buildsProps` (~line 728) passes both `targets` and `builderSnapshot` into `BuildsColumnContent`, which forwards them to every `BuildRow` (memoized at `build-results.tsx:251`). So each pointer move re-renders all rows.
- The rows only read `targets` and `builderSnapshot` at click time (`BuildActions` building a DIM loadout or saving).

Steps:
1. Add a ref that always holds the latest `{ targets, builderSnapshot }` and pass a stable getter (`getBuilderState`) down instead of the values. Update `BuildsColumnContentProps`, `BuildResults`, `BuildRow`, and `BuildActions` to call the getter where they used the props.
2. Check whether anything in the row actually renders from `targets` (for example a "meets target" highlight). If so, pass only the minimal derived value and memoize it so it only changes when the row's display would change.
3. In `buildsProps` deps, replace `armoryQuery` with `armoryQuery.refetch` (stable) and pass `onEquipped` via `useCallback`.

### 1b. Memoize the left column

Same file. `ExoticPicker`, `FragmentPicker`, `TuningControls`, `SetListControls`, and the inline `renderSetRow` (~line 647) are not memoized, so every panel render (slider move, worker message) redraws ~250 tooltip roots, ~120 images, and ~100 checkboxes.

Steps:
1. Extract `renderSetRow` into a `memo`'d `SetRow` component.
2. Wrap `ExoticPicker`, `FragmentPicker`, `TuningControls`, `SetListControls` in `memo`.
3. Wrap the handlers they receive in `useCallback`: `toggleFragment`, `onExoticSelect`, `togglePin`, `toggleSet`, `setSetFilter`, `onClassChange`, `setTarget`. They already use functional state updates, so deps are `[]` or a single stable value.
4. Extract each stat slider row into a `memo`'d `StatTargetRow` so a drag re-renders one row.

### 1c. Keep results mounted across searches

File: `src/components/builder/builds-column-content.tsx` (~lines 160-185)

`showLoading ? <BuildsLoading/> : result ? <BuildResults/> : null` unmounts the whole result list at the start of every run and remounts it when results land. This is the biggest single jank moment and also loses each row's open state.

Steps:
1. Render `BuildResults` whenever `result` exists, regardless of `showLoading`.
2. Render `BuildsLoading` above or overlaid on it while `showLoading` is true (a thin bar at the top of the column is enough; optionally dim the stale list with `opacity`).
3. Row keys are already `pieceIds.join("|")`, so unchanged builds keep their fibers. Confirm expanded rows survive a re-run.

### 1d. Lighten collapsed rows

File: `src/components/builder/build-results.tsx`

`StatGlyph` (~line 140) is a `TooltipLabel` wrapping `next/image`, rendered seven times per row header (~line 323). That is ~350 tooltip roots for 50 rows, all showing the same six stat names.

Steps:
1. In the collapsed header, render a plain `<img>` with `alt` and `title` set to the stat label, `loading="lazy"`, `decoding="async"`, explicit width/height. No tooltip.
2. Keep `TooltipLabel` only inside the expanded breakdown.
3. Do the same for the exotic icon and set badges in the collapsed header if they use `TooltipLabel`.

### 1e. Isolate high-frequency worker messages

File: `src/lib/optimizer/optimizer-store.ts` (~lines 109-117)

`ceilings` messages (up to ~50 during the inline phase) and throttled refinement progress (5/s for up to 45 s) both land in the store snapshot, re-rendering `BuilderPanel` and therefore the left column.

Steps:
1. Put `refinement.progress` in its own `ValueStore` (see `src/lib/value-store.ts`) and subscribe only in the component that displays it (`SearchStatus` or equivalent).
2. Throttle `ceilings` writes to ~100 ms or one rAF, and read `ceilings` only inside the `StatTargetRow` from 1b so the rest of the column bails out.

### 1f. First-render polish (lower priority)

File: `src/components/builder/builder-panel.tsx`

- `getStatModHashes`, `getTuningPlugHashes`, `getArtificeModHashes` (~lines 286-294) each scan the full item table (~10-20 ms each) inside `useMemo` on the first ready render, but are only needed when a row is expanded. Compute them lazily in `BuildActions` (they are memoized per manifest), or warm them in `requestIdleCallback` after the manifest is ready. The same warm-up helps the sidebar's first Edit (see 3e).
- `selectedExotic` (~lines 447-452) starts `null` and is resolved by name in an effect, causing a second full render on mount. Store the exotic name as state and derive the index with `useMemo`.

## Phase 2: Armor table (`/armor`)

### 2a. Sort once, filter per keystroke

File: `src/components/armor-table/armor-table.tsx` (~lines 222-227)

`filtered` memo filters `rows` then calls `sortRows` on the result, so every deferred search change and facet toggle re-sorts (collator compares on ~1,000 rows). `Array.filter` preserves order, so sort first.

Steps:
1. `const sorted = useMemo(() => sortRows([...rows]), [rows, sortRows])`. Note `sortRows` sorts in place today; pass a copy or make it return a new array.
2. `const filtered = useMemo(() => sorted.filter(...), [sorted, facets, searchTokens])`.
3. Optional: precompute the lowercased name in the `rows` memo so `looseNameMatch` (`src/lib/armor-table/search.ts`) skips `toLowerCase` per row per token.

### 2b. Stop the toolbar, headers, and drops feed re-rendering on scroll and hover

Same file. `ArmorTable` re-renders on every keystroke (twice, due to `useDeferredValue`), every virtualizer range change, and every column hover (`hoveredCol`, ~lines 244-252). Everything except `ArmorRow` is unmemoized, and these props are recreated per render: `statOptions` (~line 197), `clearFilters` (~231), `setFacet` (~236), `onTablePointerOver` (~245), `togglePinnedSet` / `togglePinnedArchetype` (~254-257). Also `options={[...statOptions, none]}` in `armor-table-toolbar.tsx` (~line 152) and `tuningOptions` in `filter-cascade-menu.tsx` (~line 156).

Steps:
1. Hoist `statOptions` and the tuning options array to module constants (they derive only from static `STAT_*` tables).
2. Wrap the five handlers above in `useCallback` (functional updates, `[]` deps).
3. Wrap `ArmorTableToolbar`, `SortMenu`, and `NewDropsFeed` in `memo`.
4. Move `hoveredCol` state into a `HeaderRow` component that attaches the pointerover listener through the table ref, so hover re-renders only `<thead>`.

### 2c. Skip the image optimizer for row icons

Files: `src/components/armor-table/armor-table-row.tsx` (~lines 66-72), `src/components/armor-table/new-drops-feed.tsx` (~lines 147-153)

These `next/image` uses go through `/_next/image` for 32 px Bungie icons, causing a burst of server round-trips while scrolling. `sort-menu.tsx` already passes `unoptimized`. Add `unoptimized` (the CSP already allows `img-src https://www.bungie.net`), or switch to a plain lazy `<img>`.

### 2d. Optional

- `loadTableState()` runs twice on mount (`armor-table.tsx` ~line 87 and `use-armor-table-sort.ts` ~line 32). Pass the restored sort into the hook to parse once.

## Phase 3: Loadouts sidebar and editor drawer

### 3a. Stop drawer keystrokes and cell clicks from re-rendering every mod cell

File: `src/components/loadouts/loadout-editor-drawer.tsx`

`EditorForm` (~line 461) holds `name`, `notes`, `placement`, `subclassItem` and renders five `PiecePanel`s plus the subclass column. Nothing below is memoized; `onChange={(update) => updatePieceChosen(piece.instanceId, update)}` (~line 664) and `costOf` (~lines 384, 500) are new per render. Result: 300-500 `ModCell`s (each a `TooltipLabel` plus `next/image`) re-render on every keystroke in Name or Notes, and a click on one cell re-renders all five panels.

Steps:
1. Move the Name and Notes inputs into a small child component that owns its own state and reports the value on submit (or on blur), so typing never re-renders `EditorForm`.
2. `memo(PiecePanel)`. Give it one stable `onChange(instanceId, update)` via `useCallback`, and memoize `costOf` on `mods.catalog`. `problems` is already memoized.
3. `memo(ModCell)` in `loadout-mods-editor.tsx` with a stable `onPick(option)` handler instead of the per-render closure (~lines 350-359).
4. After this a cell click should re-render one panel and a keystroke none. Verify with the Profiler.

### 3b. Memoize subclass validity

Files: `src/components/loadouts/loadout-editor-drawer.tsx` (~line 534), `src/lib/loadouts/subclass.ts` (~lines 88-165), `src/components/loadouts/loadout-details-dialog.tsx` (~line 102)

`subclassSelectionValid` calls `subclassOptions`, which rebuilds the subclass catalog (five socket scans plus per-plug description joins) on every render.

Steps:
1. Memoize `subclassOptions` per `(manifest, classType, subclass)` with a `WeakMap<Manifest, Map<string, …>>`, following `src/lib/manifest/memo.ts`.
2. Compute validity in a `useMemo` keyed on `subclassItem`.

### 3c. Let the drawer slide before the grids mount

File: `src/components/loadouts/loadout-editor-drawer.tsx` (~line 706), `src/components/ui/drawer.tsx` (~line 125)

`EditorForm` mounts synchronously when `open` flips, creating ~550 tooltip roots and images before the 450 ms slide can begin.

Steps:
1. Render the drawer header immediately; gate the five piece columns and subclass column behind `const showGrids = useDeferredValue(open)` (or set a flag inside `startTransition` in an effect) so the heavy mount overlaps the animation.
2. Replace per-cell `TooltipLabel` with one Tooltip root per grid. Base UI 1.8 supports detached triggers: `Tooltip.createHandle()` plus `<Tooltip.Trigger handle={h} payload={option}>`. Check `node_modules/@base-ui/react/tooltip` for the exact API before using it. A native `title` is the fallback.
3. Mod icons are already `unoptimized`; a plain `<img>` removes ~5 hooks per cell if step 2 is not enough.

### 3d. Stop route changes re-rendering the sidebar rows

File: `src/components/loadouts/loadouts-list.tsx` (~lines 397-417)

`optimizeLoadout` lists `pathname` in its deps. `usePathname` changes on every tab switch, so the callback identity changes and every mounted `LoadoutRow` re-renders (~15-20 rows, each with ~13 tooltip chips and image lookups).

Steps:
1. Keep `pathname` in a ref updated each render and drop it from the deps. `router` from `useRouter` is stable.
2. Also hoist the `subclass` section object literal (~lines 690-693) into a `useMemo` keyed on the open loadout, so sidebar re-renders while the drawer is open do not re-render `EditorForm`.
3. Optional: fold the chip derivations in `loadout-row.tsx` (~lines 247-304: set bonuses, super socket scan, artifact `Set`, hashtag regex) into the existing `resolved` memo.

### 3e. Lower priority

- `PlugIcon` / `ManifestIcon` in `loadout-row.tsx` (~lines 76-164) wrap every chip in `TooltipLabel` (~13 per row). Use one shared tooltip handle per chip strip, or `title`.
- Warm `getModCatalog(manifest)` in `requestIdleCallback` once the manifest is ready so the first Edit does not pay two full item-table scans (~20-40 ms). Pairs with 1f.

## Things that are already fine (do not touch)

- Optimizer worker lifecycle: module singleton, deduped by input key, survives route switches (`optimizer-store.ts`).
- Raw progress goes through a `ValueStore`; the rAF smoother never sets React state per frame.
- Manifest scans are memoized per manifest (`memoByManifest`).
- Builder selections: read once in a `useState` initializer, saved with a 300 ms debounce.
- Armor table: rows are `memo`'d with stable props, search is deferred, sorting uses a shared `Intl.Collator`, localStorage writes are debounced, virtualizer setup is standard.
- Loadouts list: `pieceMap` built once, `Map.get` lookups, virtualizer keyed by id, React Query mutations patch the cache, closed drawer content is unmounted.
- Bundle size: largest client chunks are React DOM, Next runtime, and Base UI; no obvious bloat. Phosphor icons are imported by name and tree-shake.
